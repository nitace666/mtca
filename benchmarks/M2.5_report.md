## 1. 项目概览（M2.5 范围）

M2.5 在 M1/M2 的"长期记忆 + 召回"基础上，补齐了 4 个产品级能力：

1. **4 象限分段**：每段带 `(urgency, importance, emotion, expires_at, urgent_state)` 5 字段，
   按 Eisenhower Matrix 划分到 Q1/Q2/Q3/Q4，每象限独立衰减曲线。
2. **多因子打分公式**：替换 M1 的线性 `-1/tick` 衰减，按象限 half-life 指数衰减，
   引入 f_urgency / f_importance / f_emotion / f_reference 4 因子加权。
3. **紧急追踪**：`urgent_tracker` 3 状态机（`tracking → expired → completed / postponed / important`），
   GUI 顶部红条 + 30s 自动刷新；用户通过 CLI `/紧急 /完成 /延期 /重要` 直接干预。
4. **情感自动提取**：LLM 提取 6 类 emotion（positive / excited / anxious / neutral / negative），
   喂进多因子 f_emotion，让"高情绪浓度"段在 rerank 中更靠前。

**新增第 9 铁律**：「重要记忆永不遗忘」。3 个不遗忘例外（Q1 锁底 / URGENT 不衰减 / /重要 冻结）
在多因子公式中显式实现。

## 5. 第 9 铁律实现详解（铁律 9：重要记忆永不遗忘）

> 实现位置：`src/compress/multi_factor_score.py::calculate_score`
> 与 `src/lifecycle/urgent_tracker.py::handle_response(action="important")`

### 5.1 三个不遗忘例外

```python
# src/compress/multi_factor_score.py
def calculate_score(seg: dict, now_ms: int) -> tuple[float, str]:
    ...
    # 1. /重要 段（current_score ≥ 10000）：直接锁定 score 不变。
    if current_score >= 10000.0:
        return float(current_score), "L1"
    # 2. URGENT 段（用户在追踪）
    if seg.get("urgent_state") == "tracking":
        f_time = 1.0
    # 3. Q1 锁底
    ...
    return new_score, _determine_tier(new_score, quadrant)
```

```python
# _determine_tier：第 9 铁律加强
if quadrant == "Q1" and score < 30.0:
    return "L3"        # Q1 锁底：宁可 L3 也不 L3_hidden
```

### 5.2 验证结果（benchmarks/_m257_iron_rule.py）

**总计：3/3 PASS（9 个子 case 全过）**

#### 验证 1：Q1 锁底

| Case | 输入 | 输出 | 判定 |
|------|------|------|------|
| 1.1 | Q1 + score=5 + 1 年前 + anxious | tier = **L3** | ✅ PASS（不能 L3_hidden） |
| 1.2 | Q1 极端老（5 年前）+ negative | tier = **L3** | ✅ PASS |
| 1.3 | 反向：Q4 + score=5 + 1 年前 | tier = **L3_hidden** | ✅ PASS（对照组验证锁底是 Q1 特权） |

#### 验证 2：URGENT 不衰减

| Case | 输入 | 输出 | 判定 |
|------|------|------|------|
| 2.1 | URGENT 段 + 1 年前 | score = **148.00**, tier = L1 | ✅ PASS（远 > 50，未衰减） |
| 2.2 | 对照：普通段 + 1 年前 | score = **0.00**, tier = L3_hidden | ✅ PASS（衰减生效） |
| 2.3 | URGENT vs 普通对比 | 148.0 / 0.00 ≈ **∞ 倍** | ✅ PASS（差距悬殊证明不衰减生效） |

> **关键观察**：URGENT 段 1 年后 score 148.00，普通段 0.00——148 倍差距。
> 实现：`f_time = 1.0` 在 `urgent_state=='tracking'` 时覆盖默认指数衰减。

#### 验证 3：/重要 冻结

| Case | 输入 | 输出 | 判定 |

## 6. Recall 改善（benchmarks/_m257_recall_check.py）

> GT DB：`tests/_tmp_ground_truth/ground_truth.db`（100 段 / 50 session / 410 messages）
> 测试集：`benchmarks/test_set.json`（50 case）
> 判定：recall 返回段的 `topic_label` 包含 expected_query 关键词 → hit
> 备份恢复：脚本跑完自动 `ground_truth.db.m257bak` → `ground_truth.db`，不污染仓库

| 场景 | hit_rate@1 | hit_rate@3 | 备注 |
|------|-----------|-----------|------|
| **A) 旧 FTS5（baseline）** | **0.160** | **0.160** | 与 M2_accuracy_report baseline 一致 |
| **B) + facts 通道（C1 思路）** | **0.900** | **0.940** | offline fallback（user msgs 当 facts）|
| **C) + emotion 多因子（M2.5.6）** | **0.900** | **0.940** | emotion 通过 f_emotion 间接作用 rerank |

### 6.1 数字解读

- **Baseline 0.16 = 历史基线**：与 M2 报告完全吻合（`M2_accuracy_report.md`）。
- **+ facts 0.90 / 0.94 是理论上限**：本脚本用 offline fallback 把"用户原话"当 fact，
  等同于把 ground truth 完整事实喂给 recall 通道（对比 C1 LLM 抽取 16/50 case
  仅得到 hit_rate@3=0.380）。真实环境下 LLM 抽取率决定实际提升。
- **+ emotion 无额外 hit_rate 提升**：因为 `recall_engine` 的 rerank 走 Jaccard + current_score，
  emotion 只通过 f_emotion（0.8~1.2）间接影响 score；GT DB 段初始 score 都是 100，
  f_emotion 影响幅度有限。**这是 M2.5.6 已知限制**（见 §7）。

### 6.2 与 C1 真实数据对比

| 指标 | C1 真实（LLM 抽取 16/50） | 本脚本 offline（50/50） | 倍数 |
|------|--------------------------|------------------------|------|
| hit_rate@3 | 0.380 (19/50) | 0.940 (47/50) | 2.5× |
| hit_rate@1 | 未测 | 0.900 (45/50) | — |
| 抽取 case | 16/50 (32%) | 50/50 (100%) | 3.1× |

> **长期预期**：真实使用下 LLM 抽取 fact 累积，hit_rate 会从 0.38 持续上升
> （C1_validation_report.md 结论）。
