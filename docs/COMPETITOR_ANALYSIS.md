## 2. 主流方案详解（关键 3 个 + 借鉴点）

### 2.1 Letta (MemGPT) —— 分层思路最接近我们

**核心设计**：
- 三层记忆：**核心记忆**（in-context，总加载）+ **召回记忆**（最近 N 条对话）+ **归档记忆**（向量 DB，仅查询时拉）
- LLM 主动决定"哪些记忆进核心"
- 用户也能手动改

**优点**：
- ✅ 分层思路清晰：always-loaded vs search-loaded
- ✅ 解决了"长期记忆压垮上下文"问题
- ✅ 学术背景扎实（UC Berkeley 团队）

**缺点**：
- ❌ 用户必须手动管理"哪些进核心"——**心智负担重**
- ❌ 没有时间触发，全靠 LLM/用户主动
- ❌ 核心记忆容量有限（典型 2000 tokens）
- ❌ 归档记忆全靠向量相似度，没时间维度

**MTCA 借鉴 + 改进**：
- **学**：分层架构思路（核心 / 归档）
- **改进**：
  - 核心记忆 → 用静默态 `active` 自动维护（用户零操作）
  - 时间维度 → retention 引擎自动下沉
  - 容量 → 不限（SQLite），按需展开

### 2.2 Zep / Graphiti —— 矛盾检测最强

**核心设计**：
- **知识图谱**：subject-predicate-object 三元组 + 时间戳
- 每条 fact 有 `valid_from` / `valid_to`
- 当新 fact 与旧 fact 矛盾时，旧 fact 自动 `invalid_until = new_fact_time`
- 支持"事实演化"：用户从 A 城市搬到 B 城市，旧地址自动失效

**优点**：
- ✅ 矛盾检测一流：自动识别事实变化
- ✅ 时效边（temporal validity）建模严谨
- ✅ 适合企业知识管理（合规、审计）

**缺点**：
- ❌ 需要维护完整知识图谱——存储 + 维护成本高
- ❌ 对话场景下"事实"和"观点"分不清，**过度失效**
- ❌ 图遍历查询延迟高
- ❌ 学习曲线陡

**MTCA 借鉴 + 改进**：
- **学**：矛盾检测逻辑（`supersedes` 关系）
- **改进**：
  - 不上图谱——只在 segments 之间用 `superseded_by` 字段
  - 限制触发：仅同 topic_label + 90 天内 + active 段 ≤ 10
  - 用户可覆盖："不是 supersede，是分支"

### 2.3 Mem0 —— 极简主义标杆

**核心设计**：
- 单一向量存储 + LLM 提取 fact
- 有"memory decay"（分数随时间下降）
- 提供 Python SDK + TypeScript SDK

**优点**：
- ✅ 简单：2 周能上线 MVP
- ✅ 集成容易：5 行代码接入
- ✅ 有真实用户基数

**缺点**：
- ❌ 没有静默，所有记忆都参与召回 → **噪音严重**
- ❌ 没有用户主动控制（除手动 delete）
- ❌ 没有矛盾检测，新旧记忆并存
- ❌ 衰减算法简单粗暴

**MTCA 借鉴 + 改进**：
- **学**：开发节奏（先极简再迭代）
- **改进**：
  - M1 一次性把"静默 + fog + 矛盾 + 重写"全做进核心，**不留技术债**
  - GUI 优先（Mem0 至今没 GUI）

## 3. 其他产品速览

### 3.1 ChatGPT Memory
- **特点**：内置于 ChatGPT，用户可手动 "remember this" / "forget that"
- **优点**：用户控制最直接
- **缺点**：无自动机制，记忆会无限膨胀；用户不知道"AI 现在记了什么"
- **MTCA 对比**：雾化 3 态 + 静默 + 骨架保留，比 ChatGPT 精细 10 倍

### 3.2 Obsidian + AI 插件
- **特点**：用户自己用 Markdown 维护笔记，AI 插件读取
- **优点**：用户 100% 控制，数据完全本地
- **缺点**：完全靠用户维护，AI 不主动组织
- **MTCA 对比**：MTCA 是"用户维护 + AI 辅助组织"，Obsidian 是"用户全维护"

### 3.3 NotebookLM / Claude Projects
- **特点**：用户上传源文档，AI 在源内检索
- **优点**：零配置，所见即所得
- **缺点**：不支持连续对话记忆，每次重新传
- **MTCA 对比**：MTCA 是连续积累，NotebookLM 是会话级

## 4. MTCA 真正差异化（护城河）

把上面 6 家产品放在矩阵里看，**MTCA 唯一同时满足的 5 个点**：

| 差异化能力 | MTCA | 任何竞品 |
|---|---|---|
| ① 本地优先 + 不可变骨架 | ✅ | ❌ 都有云依赖或可改 |
| ② 时间触发的自动静默 | ✅ | ❌ |
| ③ 用户主动雾化（细节擦除）| ✅ | ❌ |
| ④ 矛盾自动 supersede | ✅ | 仅 Zep |
| ⑤ 渐进展开（噪点→细节）| ✅ | ❌ 都没有 |

**护城河本质**：MTCA 不是"另一种 AI 记忆"，是"**人脑式记忆**"的工程化——骨架永久、细节可选、时间触发降权、AI 主动询问升级。**所有竞品都把"记忆"当数据库设计，MTCA 把"记忆"当人脑设计**。

## 5. 风险与陷阱（学自竞品）

| 竞品的坑 | MTCA 怎么避 |
|---|---|
| Letta 核心记忆容量瓶颈 | MTCA 没有 always-loaded 上限，按需展开 |
| Zep 过度失效 | MTCA 限制矛盾检测范围（同 topic + 90 天 + ≤10 段）|
| Mem0 噪音问题 | MTCA 静默态 + fog 双重过滤 |
| ChatGPT 记忆黑盒 | MTCA 全部本地 + GUI 可视化 + score_events 审计 |
| Obsidian 维护负担 | MTCA AI 自动分类 + 用户一键覆盖 |

---

## 6. 不抄什么

**主动不抄的**（避免同质化）：

- ❌ Zep 的完整知识图谱（成本高，MTCA 场景不需要）
- ❌ Letta 的 LLM 主动管理核心记忆（心智负担）
- ❌ Mem0 的"无 GUI"路线（不符合 MTCA 的"零代码"承诺）
- ❌ ChatGPT 的"AI 决定记什么"（违反铁律 6）
