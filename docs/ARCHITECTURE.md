## 1. 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│                       任意 Agent 平台                          │
│   OpenClaw / Hermes / 扣子 / Claude Code / Cursor / 其他       │
└─────────────────────┬───────────────────────────────────────┘
                      │ MCP Client  或  REST  (M2+)
                      ▼
┌─────────────────────────────────────────────────────────────┐
│                   MTCA Server（独立进程）                      │
│                                                              │
│   ┌──────────────────────────────────────────────────────┐  │
│   │ GUI（M1 优先） + MCP Server（M2） + REST API（M2）     │  │
│   └──────────────────────────────────────────────────────┘  │
│   ┌───────────────────────┬──────────────────────────────┐  │
│   │   主召回链路 (10ms)   │   辅概览链路 (100ms)          │  │
│   │   SQLite L0/L1        │   关系图 + 向量视图            │  │
│   └───────────────────────┴──────────────────────────────┘  │
│   ┌──────────────────────────────────────────────────────┐  │
│   │ 异步后台：动态打分 + 静默态转移 + 矛盾检测 + 摘要重写  │  │
│   │  (后台进程：不阻塞主交互)                              │  │
│   └──────────────────────────────────────────────────────┘  │
│   ┌──────────────────────────────────────────────────────┐  │
│   │ 存储：SQLite (WAL) + FTS5 + 关系图 + views            │  │
│   └──────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

## 2. 6 层数据流

```
                       AI Agent / 用户
                            │
                            ▼ 1. recall(query)
        ┌───────────────────────────────────────┐
        │      recall_engine 召回流程            │
        │                                       │
        │  1. 关键词/向量召回 top-k              │
        │  2. 关系图扩展（references/related_to）│
        │  3. supersede 过滤（保留 B 取代 A）    │
        │  4. silence 过滤（dormant×0.5 / silent 跳过）│
        │  5. fog 过滤（fogged_once → 提示）     │
        │  6. 加载 L1 摘要 + 必要时展开 L0       │
        └────────────┬──────────────────────────┘
                     │
                     ▼ 返回：骨架 + 摘要 + 必要时全文
```

## 3. 6 张表的关系

```
sessions (L0-骨架的会话容器)
   │ 1:N
   ▼
messages (L0-细节，用户/AI 不可变，可雾化)
   │ 聚类
   ▼
segments (L0-B + L0-骨架字段：silence / fog / supersede)
   │ 1:N
   ├──► views (L1/L2/L3 摘要，含 regen 状态)
   │      可被 fog/supersede 触发重写
   │
   ├──► score_events (打分审计)
   │
   └──► segment_relations (4 种关系：references/supersedes/related_to/derived_from)
          关系图谱查询入口
```

## 4. 关键决策（v0.4 更新版）

### 4.1 为什么 L0 拆成骨架 / 细节双层

- **骨架（不可变）**：用户主权的底线——话题存在过这件事永远不消失
- **细节（用户可雾化）**：心理卫生权——"我不要这段具体内容了"
- **AI 无任何层修改权**：保护数据完整性
- 物理擦除用 `UPDATE messages SET content=NULL` + fog 触发器白名单

### 4.2 为什么雾化不可逆

- 让用户对自己的"删除"负全责
- AI 永远不能"主动遗忘"——这违反铁律
- 替代方案"软删除"会留后门，未来某个版本可能被滥用

### 4.3 为什么静默态是时间触发

- 用户不需要主动管理每个段落的"保质期"
- 类比人脑：1 年前的事不会突然从脑子里冒出来，但被提及时能想起来
- retention 策略 + AI 询问 + ref_count 渐进升级 = 半自动化

### 4.4 为什么需要矛盾检测

- 1 年前漫剧方案 A vs 现在漫剧方案 B 单纯靠"静默"不够
- B 应该**显式取代** A，召回时直接说"已被 B 替代"
- Zep 风格的图谱矛盾检测 + 限制触发范围（仅同 topic + 90 天 + ≤10 段）

### 4.5 为什么需要关系图谱

- 时间分段是单向的，但话题演化是网状的
- 4 种关系：references（显式引用）/ supersedes（取代）/ related_to（同话题）/ derived_from（衍生）
- GUI 知识图谱视图：节点=段，边=关系，可时间倒带

### 4.6 为什么摘要要自动重写

- 雾化后 L1 摘要中提到的事实已不存在
- supersede 后旧方案的 L1 应该标记为"已废弃"
- 用户 GUI 手动"刷新摘要" 触发强制重生
- 失败时保留旧 L1（宁可旧也不丢）

### 4.7 为什么 GUI 优先

- 普通用户装不来 Python CLI
- M1 直接出 GUI MVP，时间线 + 话题树 + 雾化按钮 + 知识图谱
- 技术栈待定（PySide6 / Tauri / Electron），M1 启动前拍板
- CLI 仅作开发期辅助工具

### 4.8 为什么 LLM 后端要抽象

- 用户硬件差异大（GPU 显存 / 模型 / 网速）
- 4 种实现：Ollama / LM Studio / llama.cpp / 云 API
- 启动时检测 + 用户配置默认
- 降级链：本地大模型 → 本地小模型 → 云 API

## 5. 兼容性策略

### 5.1 与 Agent 平台并存（不冲突原则）

> **Agent 跑它的 → MTCA 在外存全文 → 调用时按需召回。两者不侵入，不抢资源。**

实现：
- MTCA 独立进程（`mtca-server`）
- 通过 **MCP Server** 或 **REST API** 对外（M2+）
- Agent 集成 MCP Client，启动时配置 MTCA 地址
- MTCA 后台异步跑打分 / 压缩 / 矛盾检测 / 摘要重写，不阻塞 Agent 进程

### 5.2 GUI 与 CLI 共存

- GUI（M1 优先）：时间线 / 话题树 / 雾化 / 知识图谱 / 用户控制
- CLI（开发期辅助）：数据库查询 / 批量操作 / 调试输出
- 用户可只用 GUI；开发者可只用 CLI

### 5.3 用户控制接口规范

```
/重要    当前段落锁定 score=10000，跳过任何压缩
/循环 X  当前段落跳过衰减（X = 周一/月初/每天/...）
/归档    当前段落视图隐藏（L0 全文仍保留）
/雾化    物理擦除 L0-细节，保留 L0-骨架，**不可逆**
```

详见 `docs/USER_CONTROLS.md`。

## 6. 性能与扩展

### 6.1 性能基线（M1 验收）

| 指标 | 目标 |
|------|------|
| 主召回延迟 (P95) | < 50 ms |
| 关系图扩展 (P95) | < 30 ms（≤ 50 个相邻段）|
| 矛盾检测（异步） | < 5 秒 / 段（不阻塞主交互）|
| 摘要重写（异步） | < 10 秒 / 段 |
| 后台打分开销 | < 10 ms / 段落 |
| GUI 启动 | < 5 秒 |
| 安装启动 | < 30 秒 |

### 6.2 横向扩展（M5 之后再考虑）

- 多用户隔离：不同 `mtca.db` 文件
- 跨设备同步：可选（用户提供 Nextcloud / iCloud Drive 路径）
- 多 Agent 同时接入：SQLite WAL + 行级锁天然支持
- 知识图谱分布式：超 10k 段后考虑 Neo4j 替换 SQLite 关系表
