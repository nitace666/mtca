# MTCA v0.4 方向调整

> **日期**：2026-07-04
> **触发**：老板对设计哲学的关键裁决
> **影响范围**：8 条铁律 / 5 层结构 / M1 任务表 / GUI 定位 / LLM 抽象 / 网络访问
> **状态**：已落地到 README.md + DEVELOPER_PLAN.md

---

## 1. 核心裁决

> **"如果用户没有自主权，和市面其他产品没区别了。"** —— 老板原话

MTCA v0.3 的「L0 绝对不可变」虽然保护了数据完整性，但**剥夺了用户的「心理卫生权」**——
用户没有"我不要这段记忆了"的能力。v0.4 重新定义边界：

- **L0 不可变 = AI 无权改/删**（不是用户无权）
- **用户主权 > 数据完整性**
- **删除 = 雾化细节**（话题骨架永久保留，细节物理擦除）

---

## 2. 核心变化

| 旧 (v0.3) | 新 (v0.4) | 原因 |
|---|---|---|
| L0 不可变（绝对） | L0 双层：骨架用户/AI 都不可变，细节 AI 不可变/用户可雾化 | 用户主权 > 一切 |
| 不支持删除 | `clear → fogged_once → archived` 三态 | 用户必须有"心理卫生权" |
| 召回行为固定 | 雾化后首次召回返回「已删除 + 关键词」| 显式告知边界 |
| CLI 优先 | GUI 优先 | 普通用户装不来 Python CLI |
| 单一 LLM 假设 | 抽象 LLM 接口（Ollama / LM Studio / llama.cpp / 云 API）| 用户硬件差异大 |
| 本地无网络端口 | 预留 0.0.0.0 端口，LAN/远程可启用 | 多设备 / 异地访问需求 |
| M1 任务是 CLI 时间线 | M1 任务是 GUI MVP（时间线 + 话题树 + 雾化按钮）| 视觉优先于命令行 |
| L0-A / L0-B 双层 | L0-骨架 / L0-细节 + L0-B | 拆出"骨架"作为可独立保留下来的最小记忆单位 |

## 3. 新增核心概念

### 3.1 雾化（Fog）

**定义**：用户将一个段落从 `clear` 状态推进到 `fogged_once` 再到 `archived` 的过程。底层操作是**物理擦除 L0-细节**，但 L0-骨架（话题标题/时间/关键词/锚点句）保留。

**三态行为**：

| 状态 | AI 召回反馈 | 转移规则 |
|---|---|---|
| `clear` | 完整 L0 原文 | 用户 `/雾化` → `fogged_once` |
| `fogged_once` | 「片段已删除，关键词：xxx」+ 锚点句 | 触发 1 次后 → `archived` |
| `archived` | 不再主动召回（除非用户直接搜关键词）| 永久 |

**约束（铁律 4）**：
- 雾化**不可逆**——用户责任自负
- AI 无 /雾化 权限（API 也不接受此命令）
- 骨架（话题标题 / 时间 / 关键词 / 锚点句）**永远保留**

**设计意图**：
- 不让话题"消失得无影无踪"——AI 仍能感知"这话题存在过"
- 但 AI 不能再展开"具体说了什么"
- 是用户「心理卫生权」和「上下文连续性」的中间态

### 3.2 L0 双层结构

```
┌──────────────────────────────────────────────┐
│ L0-骨架  不可变  用户/AI 都无权删              │ ← 话题标题 / 时间 / 关键词 / 锚点句（≤20 字）
├──────────────────────────────────────────────┤
│ L0-细节  AI 不可变 / 用户可雾化                │ ← 完整对话 / 工具调用 / 长文本
└──────────────────────────────────────────────┘
```

**实现要点**：
- `segments` 表加 3 个字段：`fog_state` / `fog_at` / `fog_anchor`
- 雾化操作触发 SQL：`UPDATE segments SET fog_state='fogged_once', fog_at=?, fog_anchor=? WHERE segment_id=?` + 物理擦除 messages.content（用 `UPDATE messages SET content=NULL, token_count=0 WHERE session_id=? AND seq BETWEEN ? AND ?`）
- 不可变触发器对 L0-细节 messages 表的 UPDATE 仅允许在 fog 上下文（用 `PRAGMA no_audit = on` 临时关闭，或拆出 L0-DETAIL 子表）

### 3.3 GUI 优先

- M1 直接出 GUI MVP：时间线 + 话题树 + /雾化 按钮
- **技术栈待定**（PySide6 / Tauri / Electron），M1 启动前必须拍板
- 决策依据：技术栈决定了 4 个成本维度（开发速度 / 资源占用 / 跨平台 / 维护负担），需要老板基于硬件 / 时间权衡

### 3.4 LLM 抽象

`src/llm/provider.py` 定义统一接口：

```python
class LLMProvider(Protocol):
    def generate(self, prompt: str, **kwargs) -> str: ...
    def embed(self, text: str) -> list[float]: ...
    def is_available(self) -> bool: ...
```

**4 种实现**：
- `OllamaProvider` —— Ollama HTTP API
- `LMStudioProvider` —— LM Studio OpenAI 兼容端点
- `LlamaCppProvider` —— llama.cpp Python binding
- `CloudProvider` —— OpenAI / Anthropic 兼容 API

**选择策略**：
- 启动时检测 + 用户配置默认
- 降级链：本地大模型 → 本地小模型 → 云 API
- 老板硬件 RTX 5070 12GB 跑 Qwen3.6 35B A3B 没问题，缺资源时降 7B

### 3.5 网络访问

| 模式 | 地址 | 场景 | 鉴权 |
|---|---|---|---|
| 本地 | `127.0.0.1:port` | 单机自用（M1 默认）| 无 |
| 局域网 | `0.0.0.0:port` | 多设备同 WiFi（M1 末尾可启用）| 可选 token |
| 远程 | `0.0.0.0:port` + token | 公网访问（M2+）| 必须 token |

**M1 末**：本地 + 局域网模式跑通
**M2**：远程模式 + token 鉴权 + HTTPS

### 3.6 静默态（Silence）：时间触发的自动归档

> **核心机制**：区别于 fog（用户主动），silence 是**时间触发的系统行为**。两轴正交。

**两轴状态机**：

| 维度 | 触发者 | 三态 | AI 召回行为 |
|---|---|---|---|
| **fog** | 用户 `/雾化` | clear / fogged_once / archived | 已删+关键词 → 不提 |
| **silence** | retention 引擎 | active / dormant / silent | 完整 / 分数 ×0.5 / 不主动召回 |

**silence 三态可双向流动**（升级和降级都允许）：

```
            ┌────────┐
   promote  │ silent │  demote
   ◄────────┤        ├──────────►
            └────┬───┘
                 │ promote
                 ▼
            ┌────────┐
   promote  │dormant │  demote
   ◄────────┤        ├──────────►
            └────┬───┘
                 │ promote
                 ▼
            ┌────────┐
            │ active │
            └────────┘
       （任何升级到此 → 重新计时）
```

**5 条铁律**（静默态专属）：

1. **升级 = 重新计时**：silent → dormant → active 任何一次升级，`promoted_at = now`，重置静默期
2. **降级 = 时间衰减**：active 段 `promoted_at + retention_days` 后未再被引用 → 降 dormant → silent
3. **双向都允许**：用户心血来潮启用旧话题 → 一阵子不聊 → 自动回 silent（用户无需每次手动管）
4. **用户可锁定**：GUI 标"永久活跃" → 永不下沉
5. **用户可强制下沉**：GUI 手动"提前静默" → 跳过 dormant 直接 silent

**AI 询问机制**（仅 silent 段被引用时触发，不骚扰）：

- AI 召回时附带提示：「你 X 月前做过 Y（已静默），当前相关，是否启用？」
- 用户说"是" → ref_count++，升 dormant，ref_count ≥ 阈值（默认 3）自动升 active
- 用户说"否"或忽略 → 保持 silent，**7 天内不重复问**（防骚扰）

**字段扩展**（segments 表）：

```sql
ALTER TABLE segments ADD COLUMN silence_state    TEXT DEFAULT 'active';   -- active/dormant/silent
ALTER TABLE segments ADD COLUMN promoted_at      INTEGER;                  -- 上次升级时间（重新计时锚点）
ALTER TABLE segments ADD COLUMN ref_count        INTEGER DEFAULT 0;       -- 用户"是"次数
ALTER TABLE segments ADD COLUMN last_ask_at      INTEGER;                  -- 防骚扰（7 天内只问 1 次）
ALTER TABLE segments ADD COLUMN user_retention_days INTEGER;               -- 用户覆盖（NULL=用策略默认）
```

**默认 retention 策略**（GUI 可改）：

| 话题类型 | retention | dormant 期 | 升级阈值 |
|---|---|---|---|
| 编程/技术 | 365 天 | 30-365 天 | ref_count ≥ 3 |
| 工作项目 | 180 天 | 14-180 天 | ref_count ≥ 5 |
| 生活/娱乐 | 30 天 | 7-30 天 | ref_count ≥ 2 |
| 健康/财务 | 永久 | 不静默 | — |

**AI 自动分类**（新段创建时）：

- 调 `src/llm/provider.py` 零样本分类话题类型
- 用户 GUI 一键覆盖："这段保留 1 年" / "这段永久活跃"

### 3.7 矛盾检测（Contradiction Detection）

> **痛点**：1 年前漫剧方案 A vs 现在漫剧方案 B，靠静默/打分都不够——B 应该**显式取代** A，而不是共存。

**触发**：新段落创建时，异步检查最近 90 天、同话题的 active 段落。

**方法**：LLM 零样本判断
```
Prompt: "段落 A 说 X，段落 B 说 Y。两者是否矛盾？矛盾程度（minor/major/full）？"
Output: {contradicts: bool, level: str, reason: str}
```

**Schema 扩展**：

```sql
ALTER TABLE segments ADD COLUMN superseded_by        TEXT;       -- 取代本段的新段 segment_id
ALTER TABLE segments ADD COLUMN supersedes_count     INTEGER DEFAULT 0;  -- 本段取代了几条旧段
ALTER TABLE segments ADD COLUMN contradiction_level  TEXT;       -- 'minor' | 'major' | 'full'
```

**AI 召回行为**：

| 状态 | 召回反馈 |
|---|---|
| `superseded` 旧段 | "你 1 年前的 A 方案已被 B 取代（2026-07-04）" + B 的 L0-骨架 |
| 取代者 B 段 | 正常全文 + "本方案取代了 A" 标注 |

**用户可覆盖**：GUI 右键 A → "A 不是 supersede，是分支" → 撤销 supersede 关系，标记为 `related_to`

**实现**：`src/lifecycle/contradiction_detector.py`
- 异步执行（新段入库后触发，不阻塞）
- 仅检查同 `topic_label`、最近 90 天、active 段 ≤ 10 个
- 每次 ~10 次 LLM 调用，可接受

### 3.8 多向引用图谱（Reference Graph）

> **正交于话题分段**：段与段之间是网状关系，不是单向时间线。

**4 种关系类型**：

| 类型 | 含义 | 触发 |
|---|---|---|
| `references` | 显式引用（A 提到 B）| LLM 检测对话内容 |
| `supersedes` | 取代（旧 A 被新 B 替代）| 矛盾检测自动生成 |
| `related_to` | 同话题不同角度 | 话题分类相同自动生成 |
| `derived_from` | 衍生（B 是 A 的后续/分支）| 时间相邻 + 关键词重叠 |

**Schema**：

```sql
CREATE TABLE segment_relations (
  relation_id    TEXT PRIMARY KEY,
  seg_a_id       TEXT NOT NULL,
  seg_b_id       TEXT NOT NULL,
  relation_type  TEXT NOT NULL,             -- 见上 4 种
  weight         REAL DEFAULT 1.0,          -- 用于排序
  auto_created   INTEGER DEFAULT 0,         -- 0=用户标 / 1=LLM 生成
  created_at     INTEGER NOT NULL,
  expires_at     INTEGER,                   -- 临时关系（如 supersedes 被撤销）
  FOREIGN KEY (seg_a_id) REFERENCES segments(segment_id),
  FOREIGN KEY (seg_b_id) REFERENCES segments(segment_id)
);

CREATE INDEX idx_relations_a ON segment_relations(seg_a_id);
CREATE INDEX idx_relations_b ON segment_relations(seg_b_id);
CREATE INDEX idx_relations_type ON segment_relations(relation_type);
```

**GUI 应用**：知识图谱视图
- 节点 = 段落，圆点大小 = 重要性，颜色 = silence_state（active 亮 / dormant 灰 / silent 暗）
- 边 = 关系，箭头方向 = supersedes / derived_from
- 过滤器：日期滑块、话题、静默态
- 点击节点展开 L0-骨架 + 摘要
- 时间倒带滑块："X 月前的状态是什么样"

**核心能力**：
- 话题演化：跟随 `supersedes` 链看方案迭代
- 跨会话串联：3 个月前聊过 X，昨天又聊 X，自动连起来
- 关联召回：找 1 个段，自动带上 related_to 的 N 个

### 3.9 自动摘要重写（Auto Summary Rewrite）

> **L1/L2/L3 是视图，应该随 L0 变化自动重写，而不是过期数据。**

**触发场景**：

| 触发 | 重写范围 | 原因 |
|---|---|---|
| 段落 `/雾化` | L1/L2/L3 全部用 L0-骨架 重生 | L0-细节没了，摘要中提到的事实不再存在 |
| `supersedes` 关系生成 | 被取代段的 L1/L2 标记 `stale` | 旧方案被新方案替代 |
| 段落被 promote 到 active | dormant 期的 L1 升级为详细版 | 用户重新关注 |
| 用户 GUI 手动"刷新摘要" | 全部视图重生 | 强制刷新 |

**Schema**：

```sql
ALTER TABLE views ADD COLUMN is_stale       INTEGER DEFAULT 0;     -- 是否需重写
ALTER TABLE views ADD COLUMN stale_reason   TEXT;                   -- 原因（fog/supersede/manual）
ALTER TABLE views ADD COLUMN regen_count    INTEGER DEFAULT 0;     -- 重写次数（审计）
```

**实现**：`src/compress/regen_engine.py`
- 异步队列，不阻塞主交互
- L0-骨架 + 当前 L1 + 重写原因 → LLM 重新生成 L1
- 失败时保留旧 L1（宁可旧也不丢）
- 用户可关闭自动重写（"摘要稳定"模式）

**降级**：本地 LLM 不可用时，标 `stale` 但不重写，下次启动时重试

### 3.10 召回增强（Recall Enhancement）

> 关系图 + 矛盾检测 + 摘要重写，**一起** 让召回更准。

**召回流程升级**：

```
query
  │
  ▼
1. 关键词/向量召回 top-k 段（基础）
  │
  ▼
2. 关系图扩展：拉取 related_to / references 的相邻段
  │
  ▼
3. supersede 过滤：若段 A 被 B 取代，只保留 B（除非用户显式搜 A）
  │
  ▼
4. silence 过滤：dormant ×0.5 分数 / silent 不进默认召回
  │
  ▼
5. fog 过滤：fogged_once 返回「已删 + 关键词」/ archived 跳过
  │
  ▼
6. L1 摘要 + 必要时展开 L0
  │
  ▼
返回
```

## 4. 不变（仍然坚守）

1. **数据本地优先** —— 记忆默认不出本地
2. **存储成本用户承担** —— 1–2 GB / 年可忽略
3. **Agent 互不干扰** —— MTCA 独立进程，标准 MCP / REST
4. **极简 stack** —— 不依赖 Docker / 云 / 复杂框架
5. **8 条铁律的「哲学定位」** —— 只是具体语义更新，铁律数量和指向不变
